## Source-only changes in progress

- Deleted/renamed custom-agent chat keeps the old thread title/history, but resolves future requests to Orhan instead of impersonating an unavailable saved persona. A visible notice explains this behavior.
- Orhan chat offers saved-agent mention suggestions; a recognized leading mention dispatches the exact task to that specialist through the persisted handoff/retry path. Unknown/malformed mentions remain ordinary user text. Tests were added but not run.
- AgentStore v4 persists a stable ID and deterministically maps legacy v1-v3 configurations to IDs. Chat thread v6 and workflow v2 retain those IDs; v6 also persists local reply relationships while reading v1-v5. Legacy links associate when opened under a still-current name and title-only links are associated at the moment of a rename without changing chat titles or workflow prompt content. Already-stale references from earlier renames and deleted IDs remain unresolved rather than being guessed.
- Persisted image attachments are decoded off the main thread and rendered with dimension bounds in the message. Audio payloads have a player; other non-image payloads remain MIME/name labels. This is not a PDF/video viewer.
- Press-and-hold recording in the empty composer requests microphone permission, captures AAC/M4A to cache, enforces the engine's existing 4 MiB attachment limit, and stages the real payload for review/send. Tap still launches speech-to-text; release does not auto-send. Navigation while recording releases the recorder and removes the temporary source file. This is not runtime-verified.
- Persisted audio attachment payloads are materialized to a temporary cache file and played with Android `MediaPlayer`; errors are surfaced in the bubble and the player/file are released when the bubble leaves composition.
- The attachment sheet launches a camera app with a temporary FileProvider URI; captured photos pass through shared MIME and 4 MiB validation before becoming a draft attachment. Cancel/failure removes the temporary file. This is not runtime-verified.
- Long-pressing a message now offers Reply. The composer quotes the selected message and sending stores its local `replyToId`; the relationship survives thread save/restart format migration and remains visible when the target is no longer in the retained 100-message window. This is a local conversational relationship, not a claim about remote or social replies. New v6 reads remain compatible with v1-v5; round-trip and v5 migration tests were added but not run.
- Local search now indexes all locally persisted chat thread message text (including older threads outside the 20-item recent list), displays a matching message excerpt and navigates to that message using the existing focused-source chat route. The index is computed from the existing on-device store; it adds no server call or duplicate persisted content. Runtime ordering and deleted-message behavior remain unverified.
- Sharing an attachment from the message action sheet now decodes the persisted payload, verifies its recorded size and the existing 4 MiB bound, writes a temporary cache copy under the existing FileProvider path and sends its MIME type/URI with read-grant clip data. It also includes the accompanying message text when present. This remains source-only until runtime verified.
