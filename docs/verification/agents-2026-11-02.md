## Flow traced

- `feature/agents/CreateAgentScreen.kt`: previously rendered Web / Files / Code / Image chips and stored their labels. It now states that per-agent enforcement is unavailable and does not offer pretend toggles. An existing agent's legacy tool list is shown as unenforced preferences; saving an edit passes the original list through unchanged. New agents store an empty list.
- `data/agents/AgentStore.kt`: format v2 serializes tool labels as strings. Reads v1/v2 and writes v2; there is no capability validation in the store. This slice does not rewrite or migrate stored labels.
- `app/OrhanNavHost.kt`: loads the saved agent by canonical name and passes its instructions/tools to `ChatViewModel.setAgent`; the roster also carries these values for handoff.
- `feature/chat/ChatViewModel.kt`: builds hidden context for direct chats and specialist handoffs. Both now use `agentConfigurationBlock`, so an existing specialist's preference guidance is included even when its instruction text is blank.
- `data/chat/ChatRepository.kt`: the `/api/chat` JSON includes `stream`, `mode`, `messages`, and optional `systemInstruction`. There is no selected-tool identifier or allowlist field, no capability-negotiation response in this client contract, and no local dispatch/filter step. `mode=agent` selects the shared agent pipeline.
- `feature/chat/AgentToolGuidance.kt`: recognized legacy labels only produce explicit preference wording. Unknown labels are omitted from prompt text. The wording says the engine controls access and the request does not restrict its tools.

## Contract conclusion and implementation

No selected-tool enforcement contract is present in Orhan's client request/response source. The engine may have behavior beyond this client contract, but this repository contains no evidence to claim per-agent server enforcement. No change was made to another repository or to service dispatch. The UI therefore reports per-agent restrictions unavailable instead of presenting selectable chips as real permissions. Existing v1/v2 configurations, including unknown labels, remain intact and round-trip through the existing store; chat guidance ignores unknown labels.
