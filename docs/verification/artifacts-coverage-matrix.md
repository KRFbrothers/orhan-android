## Source/runtime distinctions and blockers

- F4 statuses in the supplied file describe its author's source research. It explicitly says it did not inspect a signed-in Android runtime; those labels are not device-verified.
- S6 is a third-party web handbook, pinned in [`docs/reference/README.md`](../reference/README.md). Its `/studio` route does not prove Android Studio behavior; its mobile route list has no Artifacts/Studio page.
- Official Teamily web changelog claims are useful leads but do not resolve the Android gaps. No Teamly private backend, user credential, or provider token is copied into Orhan.
- A read-only configuration check found the existing public Supabase URL/key in ignored `local.properties` and the normal email provider enabled. No sign-in was attempted, no bypass/development JWT used, and no agent reply save was submitted. Live authenticated reply-save remains blocked on the owner's normal signed-in session.
- **Test-runner incident:** `:app:connectedDebugAndroidTest` passed 4 tests on RMX5051 / Android 16, but its UTP log declares `uninstall_after_test: true` and confirms it uninstalled both `ai.orhan` and `ai.orhan.test`. The app was present as versionCode 294 immediately before the task and absent afterward. This removed the app's private data; no app data was restored, manually rewritten, or cleared by a separate command. No further device operation is safe until the owner decides how to restore the app/data. Device state after that test is a blocker, not verification of the current source.
- **Next Artifacts slice:** first recover a safe device baseline through an owner-approved data-preserving path and verify Orhan is installed without reconstructing its history; then implement one provenance-backed saved-message artifact only after a real synthetic payload/source ID can be inspected. Media viewers remain separately blocked on real sample payloads.
